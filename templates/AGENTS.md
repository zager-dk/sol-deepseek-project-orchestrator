# Project instructions for the native Codex orchestrator workflow.

For substantial work, use the orchestrator skill to define bounded backlog
items, delegate implementation to Luna, and independently review meaningful
changes. The technical director sets scope, contracts, dependencies, and
acceptance criteria, then reviews the integrated result.

Use the optional `orchestrator-director` setup profile only when chosen. Role model/effort values are defaults; preserve explicit user model, speed, and reasoning selections. Templates inherit speed. Standard, other supported modes, and absent/unknown mode metadata do not block work. Report actual platform/model failures separately. Choose concurrency from task independence and review capacity; child roles do not delegate nested work.

Keep project state compact and project-specific. Record confirmed results,
failed checks, and checks that were not run. Never store secrets or full chat
history. Run the installer only with an explicit project path and Codex home;
its dry run is safe for inspecting the proposed file plan.


## Readiness and completion evidence

Follow the installed skill’s `references/READINESS.md` readiness contract: proportional functional/user criteria and applicable visual/audio/performance/device observations; an early finished slice compared against actual references before visual production; autonomous observed selection unless the user explicitly requests approval gates. Independent evidence must remain separate from worker/director claims; unavailable checks stay NOT VERIFIED with reasons. Repeated SAME-criterion failures require diagnosis and a changed approach, preserving acceptance. Deliver a compact passport with artifacts, evidence, limitations and launch steps. Separate first-version/rework wall time from actual model usage; missing usage stays unknown and time never implies cost.
