# Оркестратор проектов Sol + Luna

Навык Codex и локальный workflow для крупных задач. Основная сессия Sol 6.1 формирует контракт, ведёт зависимый backlog, назначает ограниченные задачи Luna или эскалирует сложную реализацию Sol senior, затем принимает интегрированный результат после независимой проверки. Astra используется для редких архитектурных консультаций.

Каталог навыка сохраняет историческое имя `sol-deepseek-project-orchestrator` для совместимых обновлений. Текущий режим использует встроенные custom subagents Codex, не требует DeepSeek или внешнего router и не работает как daemon. Начните с [QUICKSTART.md](QUICKSTART.md); описание архитектуры — [ARCHITECTURE.md](ARCHITECTURE.md).

## Роли

| Роль | Модель и reasoning | Ответственность |
| --- | --- | --- |
| Основная сессия директора (`orchestrator-director` profile) | `gpt-6.1-sol`, high | Планирует, назначает, интегрирует и принимает; не реализует код. |
| `luna_worker` | `gpt-6-luna`, medium | Ограниченная реализация. |
| `luna_reviewer` | `gpt-6-luna`, high | Независимый разбор плана и приёмка; без изменений кода. |
| `luna_state_editor` | `gpt-6-luna`, low | Узкие изменения state по указанию директора. |
| `sol_senior` | `gpt-6.1-sol`, high | Реализация после обоснованной эскалации. |
| `sol_reviewer` | `gpt-6.1-sol`, high | Отдельная read-only проверка высокого риска. |
| `astra_consultant` | `gpt-6-astra`, high | Редкая консультация, способная изменить решение. |

Шаблоны пока содержат кандидат `service_tier = "standard"`, но официальная схема Codex TOML не подтверждает явно допустимое значение для Standard; не считайте его взаимозаменяемым с API-меткой `default`. Проверьте загрузку и выбор Standard в изолированном desktop-пилоте.
Готовность: это кодовый прототип с проверяемыми installer и ledger. Проверенный маршрут native desktop сейчас заблокирован до child-вызовов: доступный delegated `spawn_agent` принимает только priority и не даёт выбрать роль или service tier; skill прочитан с диска, а не найден через `skills.list`; загрузка шести TOML в dispatch не доказана. Инструмент осмотра не показал доступных приложений или браузеров, поэтому проверить UI не удалось. Это ограничение проверенного маршрута, не всех desktop-чатов. TOML-парсер принимает `standard`, `default`, произвольные tier и любую строку effort; это не подтверждает их семантику или реальную child-диспетчеризацию.

## Установка и проверки

Установщик работает с отдельным проектом и CODEX_HOME. `--no-agent` пропускает только шесть child-ролей; root-профиль директора остаётся. Установщик использует общий `.orchestrator-install-registry.json`, системные блокировки и no-clobber для чужих файлов; при неудачном unlink запись владения сохраняется. Для Windows hooks применяются закодированные команды PowerShell, для POSIX — shell quoting. См. [INSTALL.md](INSTALL.md).

Python runtime `scripts/orchestrate.py` (после установки: `<CODEX_HOME>/skills/sol-deepseek-project-orchestrator/scripts/orchestrate.py`) управляет backlog `.codex/ORCHESTRATOR.json`. Он не запускает модели. Отдельная команда `codex` запускает сессию. Операции планирования, независимой проверки, восстановления и интеграции приведены в [QUICKSTART.md](QUICKSTART.md).

Хуки — подсказки, не enforcement-механизм. Читайте [SECURITY.md](SECURITY.md) перед включением. Тесты локального ledger не подтверждают живой вызов модели и не являются измерением экономии.

## Статистика журнала

`python scripts/orchestrate.py stats --format json` выводит приватность-фильтрованный отчет; `--format csv` выводит события с фиксированным заголовком. События находятся внутри того же `ORCHESTRATOR.json` и публикуются вместе с task/history одной атомарной заменой. Старые журналы читаются с `coverage=not_started`; их первая успешная мутация начинает `legacy_partial`, без восстановления прежней истории. Новые журналы начинают с `new_ledger`.

Task и participant references — SHA-256 псевдонимы точных UTF-8 идентификаторов с разными доменами. Они не анонимизируют данные. Свободный текст, исходные идентификаторы и поля history в отчёт не включаются. Модель и effort, если явно объявлена роль через `--owner-role` или `--reviewer-role`, отражают таблицу defaults роли, а не измеренные настройки dispatch. Все observed model/effort/tier/token/cost поля пока `null`. `elapsed_ms` — wall-clock время между зафиксированными границами состояния и включает ожидание; active/human split неизвестен. Для CSV с нулём событий coverage не представлен строками; он доступен в JSON.
