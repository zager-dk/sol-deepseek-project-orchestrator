# Sol + DeepSeek Project Orchestrator (кратко по-русски)

Это русское резюме. Полное описание подхода - на английском в
[ARCHITECTURE.md](ARCHITECTURE.md), и именно оно является основным документом.

## Что это

Навык и публичный набор файлов для Codex, который превращает работу над
проектом в связку из двух ролей:

- **корневая модель** (например GPT-6.1 Sol) - тонкий технический лид: держит
  рамки задачи, контракты, архитектурные решения и приёмку работы;
- **рабочий агент** (DeepSeek V4.1 Flash) - делает разведку по репозиторию,
  пишет код, тесты, отлаживает и отчитывается один раз.

Память проекта живет не в чате, а в файле `.codex/PROJECT_STATE.md`: это
состояние, а не история. Новый чат начинает работу уже ориентированным.

## Как выглядит режим с одним worker

```text
Root (Sol)                     Worker (DeepSeek V4.1 Flash)
  рамки и контракт  --------->  разведка, реализация, тесты, отладка
  один батч-ревью   <---------  один отчёт о завершении
  максимум одна коррекция
  обновление PROJECT_STATE
```

Дисциплина расхода контекста и внимания: один проход по рамкам, один запуск
воркера, одно ожидание, одно сгруппированное ревью, максимум один цикл
коррекции, один финальный ответ.

## Что важно понимать

- Корневая модель не переделывает разведку за воркером и не дергает его
  вопросами «как прогресс».
- Воркер не запускает вложенных агентов, не коммитит без явно разрешённого локального коммита в изолированной ветке, не пушит и не расширяет
  рамки сам.
- Мелкие задачи (опечатка, однострочная правка, форматирование) корневая
  модель делает сама: оркестрация стоит дороже, чем сама правка.
- Если маршрут до DeepSeek недоступен, это нужно сообщить, а не молча
  подменять другой платной моделью.
- Зеленый код возврата не равен приёмке: смотреть надо на то, что команда
  реально доказала.

## Установка

```bash
python scripts/install.py --project /путь/к/проекту --codex-home ~/.codex
python scripts/install.py --project /путь/к/проекту --codex-home ~/.codex --hooks
```

Установщик сначала печатает план, по умолчанию ничего не перезаписывает,
никогда не перезаписывает `PROJECT_STATE.md` и `AGENTS.md`, не трогает
`config.toml`, ключи и маршрутизацию, не ходит в сеть.

Подробности: [INSTALL.md](INSTALL.md). Первый запуск: [QUICKSTART.md](QUICKSTART.md).

## Безопасность

Перед установкой хуков прочитайте [SECURITY.md](SECURITY.md). Кратко: хуки
запускаются как локальные процессы с вашими правами, проектные хуки
загружаются только после того, как вы доверитесь слою `.codex` проекта, а их
вывод уходит в модель - поэтому секретам не место ни в `PROJECT_STATE.md`, ни
в выводе хуков.

## Честные ограничения

- В репозитории нет доступа к моделям, ключей и платных проверок.
- Точный идентификатор модели DeepSeek зависит от вашего роутера: значение из
  репозитория - это отправная точка, а не гарантия.
- Установщик не может проверить, что воркер действительно работал на DeepSeek.
- Ничего не публикуется, не пушится и не деплоится автоматически.


## Adaptive v0.2

По умолчанию остаётся один DeepSeek V4.1 Flash worker. Sol выбирает двух или
трёх, если направления независимы, имеют раздельные файлы и критерии приёмки,
а выигрыш по времени оправдывает интеграцию. Общие схемы, миграции и lockfiles
должны иметь одного владельца. Для нескольких writers обязательны отдельные
worktrees/branches от одного чистого коммита. Если безопасный запуск в этих
папках недоступен, используется один writer.

После завершения writers отдельный DeepSeek integrator собирает точные коммиты
или полные patches, проверяет общий результат и возвращает единый отчёт.
Sol делает одно сгруппированное review и максимум один цикл исправлений.
Только Sol обновляет PROJECT_STATE.md; workers и integrator его не меняют.

```bash
python scripts/install.py --project /путь/к/проекту --codex-home ~/.codex --adaptive --hooks
python scripts/verify_install.py --project /путь/к/проекту --codex-home ~/.codex --adaptive --self-test
```

Старые команды установки, GPT-5.6 Sol, роль deepseek_worker и исторический
alias astra_flash_builder совместимы. При обновлении сначала используйте
`--dry-run`, затем `--force` для управляемых файлов с резервной копией.
Существующие AGENTS.md и PROJECT_STATE.md сохраняются: правила AGENTS.md
нужно адаптировать вручную по новому шаблону. Каждый пользователь использует
свои API-ключи DeepSeek/провайдера; ключей в репозитории нет.

Параллелизм может ускорять выполнение, но добавляет API-запросы. Экономия
ресурса подписки происходит за счёт переноса реализации и отладки с Sol на
DeepSeek. Это не обещание фиксированного процента экономии или меньшего
общего счёта. Полное английское описание: [ARCHITECTURE.md](ARCHITECTURE.md).
